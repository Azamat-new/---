# СЕПАРАТОР — методология

Воронка для работы с ИИ на больших проектах. Этот документ — протокол, независимый от инструмента: что входит,
что выходит, кто что видит, что считается доказательством и когда работа возвращается назад. Эталонная реализация
для Claude Code лежит рядом (`.separator/`, `.claude/`); полная спецификация с таблицами — в `docs/SPEC.md`.

## 1. Зачем и почему именно так

Прямая линия «задача → ошибка → фикс» ломается на больших проектах по пяти причинам, и каждая стадия воронки закрывает
одну из них:

| Причина | Что ломается | Ответ воронки |
|---|---|---|
| один контекст планирует, пишет и судит | судья наследует ошибки автора; самооценка «всё хорошо» | разделение ролей, обеспеченное физически (worktree, хуки, песочница) |
| контекст переполняется историей фиксов | модель дрейфует от исходного намерения, повторяет ошибки | артефакты как единственная память; каждая стадия — свежий контекст |
| нет объективного «готово» | цикл без выхода | приёмочные критерии до кода, красный тест до реализации, механический шлюз |
| ошибки находят после реализации | самая дорогая точка | самое дешёвое опровержение раньше всего: триаж → проверка плана → спайк |
| ничего не записано | те же решения принимаются заново | реестры решений, уроков, метрик; правила человека — закон для следующих стадий |

Ускорение получается не вопреки строгости, а благодаря ей: строгость **оплачивается классом риска** (опечатка не
проходит девять стадий), человек выходит из цикла на ~80 % задач, ошибки ловятся там, где их дёшево чинить, и ни одна
воспроизведённая ошибка не оплачивается дважды.

## 2. Четыре несущих правила

1. **Артефакты — единственная память.** Стадия читает файлы, пишет файлы, и её можно повторить свежим контекстом,
   другим инструментом или человеком. Разговор не является входом ни для одной стадии.
2. **Независимость определяется тем, что стадии разрешено читать, и обеспечивается физически.** Промпт — просьба;
   пакет файлов, песочница, хук и отдельный процесс — гарантия.
3. **Каждый шлюз объективен.** Код выхода, схема, равенство множеств, хеш. Там, где суждение неизбежно, оно оформлено
   как бинарный чек-лист, который заполняет не автор.
4. **Возвраты только вверх по потоку, только со свидетельством, только со счётчиком.** «Мне не нравится» — не
   возврат. Воспроизведение становится постоянным тестом до повторной отправки (храповик). Счётчики держит скрипт,
   не агент. Любой исчерпанный счётчик заканчивается у человека.

## 3. Классы риска (сепарация)

Класс вычисляется детерминированно из путей и размера, агент может только повысить его:

| Класс | Признаки | Доля | Что проходит |
|---|---|---|---|
| **T0** тривиальный | 1 зона, ≤3 файла, ≤80 строк, порог зоны T0, нет контрактов/схем/инфраструктуры, нет неизвестных | ~30 % | триаж (пакетно) → исполнение → шлюз → холодная линза → авто-merge |
| **T1** обычный | ≤2 зоны, ≤8 файлов, без изменения публичных контрактов, обратимо | ~50 % | всё, кроме аудита плана и панели дизайнов; 1 инспектор, клиентская линза |
| **T2** рискованный | путь риска (auth, billing, миграции, публичный API/схема, lock-файлы), >8 файлов, >2 зон | ~15 % | + аудит плана, проверка контракта вторым агентом, 2 инспектора, 2 линзы, карточка слияния для человека |
| **T3** необратимый | удаление данных, внешние побочные эффекты, новая зона, архитектура, флаг человека | ~5 % | + панель из трёх дизайнов и двух судей, план отката, security-линза, необратимый шаг только после человека |

Класс считается дважды: прогноз на входе (по оценке путей) и факт на шлюзе (по диффу). Превышение дорожки
автоматически повышает класс и запускает пропущенные стадии. Утечка дефекта в зону поднимает её порог на 10 задач;
20 чистых задач подряд опускают обратно.

## 4. Стадии

Обозначения: «Видит» — исчерпывающий список входов; всё остальное для роли не существует. «Выход» — объективное условие.

### S0 Приём (широкое горлышко)
- **Кто:** триаж (дешёвая модель) и **независимая проверка намерения** (видит только дословный запрос).
- **Вход:** что угодно: фраза, баг, скриншот словами, десять мелких правок одним сообщением.
- **Выход:** `request.md` (дословно, неизменяемо), `ACCEPTANCE.md` (только ЧТО увидит пользователь: `WHEN … THE SYSTEM SHALL …`,
  без глаголов реализации), `triage.json` (класс, сигналы, пути, неизвестные, ≤5 вопросов с безопасными дефолтами,
  допущения с пометкой `intent`), `intent-check.json` (совпал ли независимый список критериев).
- **Шлюз:** класс присвоен по сигналам, у каждого критерия есть способ проверки, независимый список не расходится
  (иначе вопрос человеку). Для T2+ — «предсмертная записка»: «это выпущено и не решило задачу, потому что…».
- **Человек (H0):** только если класс ≥ T2 и неоднозначность высока, или списки разошлись, или у вопроса нет безопасного
  дефолта. Иначе дефолт записывается как допущение и показывается на карточке слияния.

### S1 Зоны ответственности
- **Кто:** код (поиск по карте) и картограф — только для непокрытых путей; картограф **не видит запрос** (зоны не
  зависят от задачи).
- **Артефакт:** `zones.json` — единственное место, где живут язык и команды проекта: пути → команды `setup/build/test/
  fast/lint/run/mutate` (`null` = неизвестно, принуждает к пробе), глобы тестов, сериализуемые ресурсы (lock-файлы,
  миграции, сгенерированные клиенты), инварианты, персона сопровождающего, порог риска, уверенность
  (`inferred` → `declared` после одной строки человека).
- **Инкрементально:** картографируется только область текущей задачи; десятилетний монолит «размечен на 1 %, и этого
  достаточно».
- **S1b Bootstrap:** зона без тестов (`test: null`) получает характеризационные тесты для области задачи до того, как
  воронка в ней работает; если проверку невозможно сделать запускаемой, верификация деградирует до «наблюдения»
  с повышением класса, и такой юнит никогда не сливается автоматически.

### S2 Разбор (декомпозиция)
- **Кто:** планировщик (только чтение кода; пишет только план) и **аудитор плана**, который видит только `dag.json`
  и переводит план обратно в критерии; скрипт сравнивает с `ACCEPTANCE.md`.
- **Выход:** `dag.json` — юниты с: одна зона, `writes` (глобы, непересекающиеся внутри волны), `test_writes` (путь
  приёмочного теста), `checks` (запускаемая команда на каждый критерий), зависимости, оценка размера, `must_not_touch`,
  интерфейс при пересечении зон. Контрактные юниты (схемы, миграции, lock-файлы) идут первыми и в одиночку; самый
  неопределённый юнит — первым.
- **Шлюз (код, 0 вызовов):** ацикличность, дизъюнктность write-set внутри волны, ≤8 файлов и ≤300 строк на юнит,
  ≤12 юнитов, каждый критерий покрыт, у каждого юнита есть проверка. Провал → планировщик один раз получает список
  нарушений; второй провал → человек.
- **T0:** ровно один юнит. **T3:** три независимых дизайна и два судьи до плана.

### S3 Распределение
- Чистый код: топологические волны, worktree на юнит, лимит одновременных писателей (≤5), бюджеты вызовов и усилий
  по классу, блокировки сериализуемых ресурсов между эпиками. Контракт хранит `base_sha`; перед следующей волной
  «красный на базе» перепроверяется, если интеграционная ветка сдвинулась.

### S4 Проверка гипотез (спайк)
- **Кто:** пробер в отдельном worktree; T2+ — второй агент проверяет контракт, не видя рассуждений пробера.
- **Что:** ≤5 утверждений, на которых держится план, ранжированных по важности × отсутствию свидетельств; самое дешёвое
  опровержение первым (grep → `--help` → трёхстрочный скрипт → одноразовый прототип); каждый новый импорт, флаг или
  ключ конфигурации сверяется с установленным артефактом.
- **Поставка:** **падающий приёмочный тест** на каждый критерий юнита. Код пробы выбрасывается; выживают отчёт и тест.
- **Шлюз:** тест существует, падает на базе по правильной причине, не помечен skip, не флакает. Опровергнутое
  утверждение → возврат в S2 со свидетельством (план был неверен, не код).

### S5 Выполнение
- **Кто:** исполнитель в изолированном worktree на ветке юнита. **Видит:** карточку, контракт, приёмочные тесты,
  персону зоны, правила человека, дефекты для исправления (с репро) и заметки предыдущей попытки. **Не видит:** чат,
  другие юниты, прозу ревьюеров; повтор — это новый агент, а не продолжение.
- **Правила:** ровно карточка, внутри write-set (хук отказывает во всём остальном); тесты проверяют, а не определяют —
  `acc_*`/`regress_*` и существующие тесты заморожены, новый тест добавить можно; если карточка или тест неверны —
  остановиться и написать `SCOPE-REQUEST`, а не обойти; все проверки прогоняются через `sep unit run` (свидетельство,
  не заявление); коммиты нейтральные (`<юнит> change set <n>`): намерение живёт в реестре, никогда в git.
- **Механический шлюз (код):** контрактные проверки, `test/lint/build` зоны, `diff ⊆ writes`, замороженные тесты
  нетронуты, нет skip-маркеров, нет секретов, флак-контроль (повтор падающего теста; прошёл со второго раза — помечен,
  не зачтён), мутанты на изменённых строках (каждый должен убить тест), класс пересчитан по факту.
  Провал → один свежий повтор со свидетельствами шлюза, затем S2.

### S6 Независимое ревью с контекстом (первый сепаратор)
- **Кто:** инспектор со свежим контекстом (T2+: две линзы — корректность и радиус поражения). Знает план и контракт,
  **не знает** рассуждений автора и прозы прошлых раундов (второй раунд — только дельта).
- **Что:** сам перезапускает шлюз (свидетельства автора — заявления, пока не воспроизведены), ищет «зелёное, но
  неправильное»: контракт соблюдён буквой, регрессии вне приёмочных тестов, ослабленные или тавтологические тесты,
  названные планом крайние случаи, опасности.
- **Находка блокирует только если** несёт воспроизведение, которое инспектор запустил (`cmd, expect, got`), или называет
  класс опасности из политики; остальное — заметки (≤5). У каждой находки есть **происхождение**: код → S5, контракт →
  S4, декомпозиция → S2, запрос → S0. Пустой список — нормальный результат.

### S7 Слепое ревью без контекста (второй сепаратор)
- **Кто:** «посторонние» в **запечатанной песочнице**: холодная линза (видит только код до и после), клиентская линза
  (+ `ACCEPTANCE.md` и команды запуска), security-линза для T3.
- **Как обеспечена слепота:** песочница строится из git (дерево, без `.git`), strip-список удаляет `CLAUDE.md`,
  `.claude/`, `.separator/`, changelog и шаблоны PR; ровно два нейтральных коммита `base` и `change`; каталог вне
  проекта со случайным именем; линза запускается **отдельным процессом** с ограничением файловых инструментов
  каталогом песочницы и хуком, отказывающим в родительских путях, истории git, окружении и сети; в план встроена
  **канарейка** — случайный токен, появление которого в вердикте означает утечку и аннулирует панель; дифф сканируется
  на «нарратив» (имя эпика, пути прогона).
- **Что:** каждая линза сначала пишет `knowledge_statement` («всё, что я знаю о том, зачем это изменение» — должно быть
  пусто), затем холодная — `inferred_intent`: что делает изменение и зачем, по мнению незнакомца. Это **тест обратного
  перевода**: несовпадение с критериями приёмки — само по себе находка (либо построено не то, либо изменение
  непонятно). Клиентская линза прогоняет каждый критерий руками и отчитывается PASS/FAIL/UNVERIFIABLE с командой.
- **Вес голоса:** пустой список исполненных команд = вес 0; линзы не знают о стадиях — их находки маршрутизирует
  контекстный агент. Разнообразие: другая семья моделей (если настроена) > другой источник свидетельств (одна линза
  исполняет, другая читает) > персона > уровень модели. Согласие S6 и S7 ≥ 95 % при наличии утечек = штамповка,
  линза переписывается.

### S8 Вердикт и слияние
- **Кто:** код — таблица решений из 22 строк, сверху вниз, первое совпадение (входы: шлюз, scope, вердикт инспектора,
  вердикты линз, совпадение намерения, удержания, счётчики, интеграция, чистота утечек, наличие свидетельств).
  Судья-агент — только при расколе линз без репро; человек — по карточке для T2/T3 и удержаний.
- **Три силы находки:** **block** — есть репро (стоит раунд, становится тестом); **hold** — репро нет, но назван класс
  опасности (auth, потеря данных, миграция, гонки, секреты/PII, горячий путь, необратимость): класс поднимается до T2,
  один верификатор пытается воспроизвести или опровергнуть, невоспроизведённое **никогда не считается опровергнутым**
  и доходит до человека; **concern** — всё остальное, бесплатно, в уроки.
- **Слияние:** `decision.json` хранит `sha256` диффа; изменение кода после вердикта аннулирует его. T0/T1 сливаются в
  `integration` автоматически с трейлерами; T2/T3 ждут карточку; `integration → main` продвигает человек по
  расписанию (H4) со стопкой карточек. Три выхода: сливки (merge), обрат (`deferred.md` → тикеты, никогда не теряется),
  осадок (эскалация).

### S9 Обучение
- Код пишет метрики на каждом шаге; ученик запускается только если были возвраты, утечки или правила. Утечка в зоне →
  порог зоны +1 на 10 задач; репро дефектов уже стали тестами; `lessons.md` ≤ 60 строк, ≤3 новых на эпик, с указанием
  слоя, который должен был поймать; повторяющиеся правила → предложения в правила по путям; правило без применения
  90 дней → кандидат на удаление; каждая утечка получает регрессионный тест.

## 5. Контроль циклов

| Счётчик | Лимит T0/T1/T2/T3 | При исчерпании |
|---|---|---|
| повторов исполнителя после провала шлюза | 1 | → S2 со свидетельствами |
| возвратов в S5 (из S6/S7) | 1 / 2 / 2 / 3 | → S2 (T2/T3 сначала повышают модель и усилие) |
| возвратов в S4 | 0 / 1 / 2 / 2 | → S2 |
| возвратов в S2 | 0 / 1 / 1 / 1 | → человек (H3) |
| возвратов в S0 | 1 на эпик | → человек («намерение нестабильно») |
| раундов интеграции на пару юнитов | 2 | пара сериализуется в один юнит, человек |
| вызовов на юнит | 4 / 12 / 24 / 40 | юнит паркуется, соседи продолжают |
| эскалаций на эпик | 3 | эпик паркуется; человеку предлагаются split/kill |

Храповик: каждая находка несёт сигнатуру; повторение сигнатуры на той же стадии невозможно — эскалация на уровень
выше; тот же хеш артефакта после возврата или то же репро снова = нет прогресса → человек немедленно. Возвраты
образуют DAG над (стадия, раунд); возврат человека сбрасывает ровно один названный счётчик, противоречие прошлому
правилу должно явно его заменить.

## 6. Человек: пять точек, и нигде больше

| Шлюз | Когда | Что видит | Варианты |
|---|---|---|---|
| **H0** | после S0: T2+ с высокой неоднозначностью, расхождение намерений, вопрос без дефолта | `questions.md`: ≤5 вопросов, дефолт и «почему» | ответить / дефолты / убить |
| **H1** | после S4 для T2/T3 | пакет контрактов: по 10 строк на юнит | утвердить / изменить / вернуть в S2 / убить |
| **H2** | S8 для T2/T3, удержаний, наблюдаемых юнитов | карточка слияния на один экран | утвердить / вернуть с причиной / убить |
| **H3** | исчерпан счётчик, невоспроизведённая опасность, раскол, недействительная панель | карточка тупика: что пробовали, два лучших варианта с ценой, «убить» третьим | вариант / правило / убить |
| **H4** | по расписанию (ежедневно) | стопка карточек, допущения `intent` для подтверждения, удержания, обрат, зоны для объявления, предложения тюнинга | продвинуть `integration → main` / откатить юнит / подтвердить / применить |

Ни один агент не задаёт вопрос человеку напрямую: вопрос — строка в файле, решение — файл. Правило записывается один
раз и не переспрашивается. Человек никогда не читает транскрипт. Отсутствие человека три дня = три дня в
`integration`, ничего в `main`.

## 7. Что делает воронку быстрее, а не медленнее

1. Человек вне цикла на ~80 % задач (касания 3 → 0,3 на задачу).
2. Утечки дефектов (самая дорогая позиция) 0,3 → 0,05 на T1 и 0,3 → 0,03 на T2 по стартовым приорам; после десяти
   прогонов в теневом режиме числа заменяются измеренными.
3. Параллельные волны юнитов там, где линия была бы восемью последовательными цепочками.
4. Маленькие контексты: выше вероятность попадания с первой попытки, короче каждый вызов.
5. Дешёвые убийства раньше дорогих стадий: триаж (0,2 вызова), проверка плана (0 вызовов), спайк (1 вызов) вместо
   N исполнений и 2N ревью.
6. Храповик: одна и та же ошибка не оплачивается дважды; правила не переспрашиваются; возобновление бесплатно.

Где воронка проиграет прямой линии: однофайловые правки с высокой вероятностью успеха — ровно дорожка T0 и обходная
дорожка (`/sep-blind` на ручной дифф), где худший случай — «прямая линия плюс один дешёвый страховочный вызов».
Токенов уходит в 2–4 раза больше, чем в чате; платой является токен, а не время.

## 8. Метрики и самонастройка

Первопроходная доходность по стадиям (цели: S4 ≥ 80 %, S5 ≥ 85 %, S6 ≥ 70 %, S7 ≥ 90 %), матрица возвратов, утечки на
100 слияний (единственная «правда»: только она автоматически повышает строгость), доля находок S7, не пойманных S6,
согласие S6↔S7, точность ревьюеров (≥70 %), гистограмма глубины поимки (должна смещаться влево), доля повышений класса
на шлюзе (<10 %), доля убийств спайком, время цикла с разделением на агентное и ожидание человека, вызовы на юнит,
инциденты харнесса. Строгость поднимается немедленно при утечке и опускается медленно с одобрения; сезонная проверка
на посеянных дефектах измеряет отзыв каждой линзы; новая модель — сброс окон и повторный аудит стадий.

## 9. Универсальность

Протокол — файлы, схемы и один CLI. Язык и команды проекта живут только в `zones.json`; все остальные артефакты
говорят двумя словами: `check` (команда с кодом выхода) и `observation` (описанный шаг со свидетельством). Тот же
цикл `sep next` крутит Claude Code, Cursor, headless-CLI любого вендора или команда людей — см.
`docs/PLAYBOOK-other-tools.md`. Внедрение с первого дня ничего не выбрасывает: скопировать `.separator/`, объявить одну
зону, десять задач в теневом режиме (карточки без слияния), объявлять зоны по мере касания, включить строгий режим,
когда нужна скорость и принуждение.

## 10. Словарь

| Термин | Значение |
|---|---|
| сепаратор / воронка | весь процесс: широкий вход, сужающиеся фильтры, два независимых сепаратора, три выхода |
| широкое горлышко | S0: входит что угодно; триаж классифицирует; вопросы пакетом с дефолтами |
| зона ответственности | пути → команды, порог риска, персона, сериализуемые ресурсы |
| юнит | единица работы одного свежего контекста: одна зона, свой write-set, свой красный тест |
| карточка (card) | весь мир исполнителя на одну страницу |
| спайк | самое дешёвое опровержение плана; поставка — падающий приёмочный тест |
| механический шлюз | проверки только скриптом: тесты, линт, scope, заморозка, мутанты, секреты |
| инспектор | независимый ревьюер с контекстом; может вернуть в S5/S4/S2/S0 |
| линза | ревьюер без контекста в песочнице: холодная, клиентская, security |
| тест обратного перевода | незнакомец описывает, что делает изменение; несовпадение с критериями — находка |
| канарейка | токен, живущий только в плане; его появление в слепом вердикте доказывает утечку |
| храповик | репро → постоянный тест до повторной отправки; пространство ошибок только сжимается |
| удержание (hold) | невоспроизведённая находка класса опасности, обязанная дойти до человека |
| сливки / обрат / осадок | merge / отложенный тикет / эскалация |
| правило (ruling) | решение человека, записанное один раз и действующее на всех последующих стадиях |
| утечка (escape) | дефект, найденный после слияния; единственная метрика, автоматически повышающая строгость |
