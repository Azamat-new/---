# Сепаратор — воронка для вайбкодинга больших проектов

> Схема в FigJam: https://www.figma.com/board/7VgCIMCMOK2WroyMvOEAxT
> Методология: [SEPARATOR.md](SEPARATOR.md) · Полная спецификация: [docs/SPEC.md](docs/SPEC.md) · Без Claude Code: [docs/PLAYBOOK-other-tools.md](docs/PLAYBOOK-other-tools.md)

## Проблема

На большом проекте работа с ИИ вырождается в одну прямую линию: задача → ошибка → исправление → ошибка → исправление.
Причины известны: один контекст одновременно планирует, пишет и судит (и судья наследует все слепые пятна автора);
контекст «гниёт» с каждым фиксом; ничего не записано, поэтому каждая сессия открывает те же грабли заново; нет
объективного критерия «готово», поэтому у цикла нет выхода.

## Идея

Работа проходит через **сепаратор**: широкое горлышко на входе, несколько фильтров, два независимых ревью, три
выхода (сливки → merge, обрат → отложенный тикет, осадок → человек). Строгость зависит от класса риска: опечатка
идёт по быстрой дорожке за две «дешёвые» вызова, миграция базы проходит все стадии и два раза встречает человека.

```
 любой ввод ─► S0 Приём ─► S1 Зоны ─► S2 Разбор ─► S3 Распределение ─► S4 Проверка гипотез
                 │ (T0: быстрая дорожка) ─────────────────────────────────────────┐
                 ▼                                                                ▼
        S5 Выполнение ─► Механический шлюз ─► S6 Ревью с контекстом ─► S7 Слепое ревью ─► S8 Вердикт ─► S9 Обучение
                 ▲                                    │ возврат с репро              │ находки → маршрутизатор
                 └────────────────────────────────────┴──────────────────────────────┘
```

Четыре несущих правила:

1. **Артефакты — единственная память.** Каждая стадия читает файлы и пишет файлы; любую стадию можно выполнить свежим
   контекстом, другим инструментом или человеком.
2. **Кто пишет ≠ кто проверяет ≠ кто судит.** Планировщик, пробер, исполнитель, инспектор и слепые линзы — разные
   процессы с разными правами, и это обеспечено физически (worktree, хуки, песочница), а не просьбой в промпте.
3. **Каждый шлюз объективен**: код выхода, схема, множество файлов, хеш диффа. «Выглядит нормально» шлюзом не является.
4. **Возвраты только вверх, только со свидетельством, только со счётчиком.** Каждая воспроизведённая ошибка становится
   постоянным тестом до повторной отправки (храповик), поэтому циклы сжимаются, а не крутятся.

## Стадии

| Стадия | Кто | Что делает | Чего не видит | Объективный выход |
|---|---|---|---|---|
| **S0 Приём** (широкое горлышко) | `sep-triage` + `sep-intent-checker` | триаж: класс T0–T3, `ACCEPTANCE.md` (только ЧТО увидит пользователь), ≤5 вопросов с дефолтами; независимая проверка намерения читает **только** исходный запрос | чат, идеи реализации | `triage.json` валиден, класс по сигналам, список критериев совпал с независимым |
| **S1 Зоны ответственности** | `zones.json` + `sep-cartographer` | карта репозитория: пути → команды проверки, порог риска, персона, замороженные тесты | текущий запрос | каждый затронутый путь в зоне с известной командой |
| **S2 Разбор** | `sep-planner` + `sep-plan-auditor` | DAG юнитов: одна зона, непересекающиеся write-set, запускаемая проверка на каждый критерий; аудитор читает **только** план и переводит его обратно в критерии | код (только чтение), другие эпики | `sep plan check`: ацикличность, дизъюнктность, размеры, покрытие критериев |
| **S3 Распределение** | код | волны, worktree на юнит, лимит WIP, бюджеты по классу | — | `schedule.json` |
| **S4 Проверка гипотез** | `sep-prober` | ≤5 утверждений плана, самое дешёвое опровержение каждого; пишет **красный** приёмочный тест | реализация | тест существует и падает на базе по правильной причине |
| **S5 Выполнение** | `sep-executor` (worktree) | реализует ровно карточку внутри write-set; все проверки через `sep unit run` (свидетельства, не заявления); нейтральные коммиты | чат, другие юниты, рассуждения ревьюеров | **механический шлюз** `sep gate`: тесты, линт, scope ⊆ write-set, замороженные тесты нетронуты, нет skip-маркеров, нет секретов, мутанты убиты, класс пересчитан по факту |
| **S6 Независимое ревью с контекстом** | `sep-inspector` (1–2 линзы) | свежий контекст, знает план; сам перезапускает шлюз; блокирующая находка = репро, которое он запустил, или класс опасности; тег стадии-виновника | рассуждения автора | `inspect-*.json`; возврат в S5/S4/S2/S0 |
| **S7 Слепое ревью без контекста** | `sep-outsider-cold`, `sep-outsider-customer` (+security для T3) | отдельный процесс в **запечатанной песочнице** (два нейтральных коммита, без истории, плана, CLAUDE.md); холодная линза пишет, что по её мнению делает изменение (тест обратного перевода); клиентская линза прогоняет каждый критерий приёмки руками | всё, кроме кода до/после (и критериев — только клиентская) | JSON-вердикт с исполненными командами; проверка утечек (канарейка) |
| **S8 Вердикт** | код (`sep decide`) | таблица решений из 22 строк: merge / возврат / удержание / эскалация; хеш диффа привязан к вердикту | — | `decision.json`; `sep merge` в `integration` с трейлерами |
| **S9 Обучение** | код + `sep-learner` | метрики, уроки (≤60 строк), решения (ADR-lite), предложения по порогам зон | — | `metrics.jsonl`, `lessons.md` |

Человек встречается с воронкой в пяти точках и нигде больше: **H0** вопросы (только T2+ или расхождение намерений),
**H1** контракты (T2/T3), **H2** карточка слияния (T2/T3, удержания), **H3** карточка тупика (исчерпан счётчик),
**H4** дайджест `integration → main`. Всё остальное идёт без него.

## Классы риска и дорожки

| Класс | Когда | S2 | S4 | S6 | S7 | Слияние |
|---|---|---|---|---|---|---|
| **T0** | 1 зона, ≤3 файла, ≤80 строк, без изменения поведения | 1 юнит | — | — | холодная линза | авто в `integration` |
| **T1** | ≤2 зоны, ≤8 файлов, без публичных контрактов | да | да | 1 линза | клиентская | авто в `integration` |
| **T2** | публичный API/схема/миграция/auth/billing, >8 файлов | + аудит | + проверка контракта | 2 линзы | клиентская + холодная | карточка (H2) |
| **T3** | необратимое, удаление данных, новая зона, архитектура | + панель дизайнов | + план отката | 2 линзы | + security | карточка (H2) |

Класс считается из путей и размера **дважды**: по прогнозу на входе и по фактическому диффу на шлюзе; фактический
класс может только повысить строгость (пропущенные стадии запускаются).

## Быстрый старт (Claude Code)

```sh
# 1. скопируйте в свой репозиторий
cp -r .separator .claude .githooks AGENTS.md CLAUDE.md <ваш-репозиторий>/
cd <ваш-репозиторий>
node .separator/bin/sep.cjs init          # policy.json, zones.json (по build-файлам), реестры, .gitignore, hooksPath
# 2. объявите зоны: .separator/zones.json — пути, команды test/lint/build, confidence: "declared"
# 3. перезапустите Claude Code (агенты .claude/agents регистрируются при старте)
node .separator/bin/sep.cjs selftest      # хуки отказывают, песочница слепа, счётчики срабатывают
```

Затем в Claude Code:

```
/sep "Добавить команду remove в CLI: `todo remove <id>` печатает `removed <id>`; неизвестный id — ошибка `no item <id>`"
```

Воркфлоу `sep-run` проведёт эпик через все стадии, остановится на шлюзе для человека (вопросы, карточка) и продолжит
после `sep answer` / `sep approve`. Итог — merge-коммит в ветке `integration` с трейлерами `Separator-Unit`,
`Separator-Diff`, `Separator-Row`; в `main` его продвигает человек.

Без Claude Code — тот же цикл `sep next` любым инструментом: [docs/PLAYBOOK-other-tools.md](docs/PLAYBOOK-other-tools.md).

## Что гарантировано и чем именно

| Гарантия | Механизм | Проверено |
|---|---|---|
| исполнитель не выходит за write-set и не трогает замороженные тесты | хук `guard-write` в `.claude/settings.json` (по `agent_type` и `.sep-role` в worktree) | `sep selftest` |
| агенты не пушат, не мержат, не переключают защищённые ветки | хук `guard-bash` | `sep selftest` |
| слепой ревьюер физически не видит план, историю, CLAUDE.md | `sep sandbox`: копия дерева через git, два нейтральных коммита, strip-список; запуск `claude -p --restricted` из каталога **вне** проекта; хук `guard-blind`; канарейка из плана ищется в вердикте | e2e: чтение файла проекта из песочницы **запрещено**; `git log` **запрещён** |
| «зелёный, но неправильный» ловится | мутанты на изменённых строках (каждый должен убить тест), запрет skip-маркеров, замороженные приёмочные тесты, повторный прогон шлюза инспектором | e2e: выживший мутант выявил непокрытый критерий A1 |
| код не меняется после вердикта | `decision.json.diff_sha256`, `sep merge` сверяет хеш; CI проверяет трейлеры | `sep merge` |
| цикл конечен | счётчики в `state.json` пишет только CLI; лимиты по классу; повтор той же сигнатуры → эскалация | `sep selftest` (ESCALATE при исчерпании) |
| харнесс проверен до доверия | `sep selftest` + `sep lint`; pre-push и CI отказывают при провале | `.githooks/pre-push`, `.github/workflows/separator-gate.yml` |

## Структура

```
.separator/
  bin/sep.cjs          CLI без зависимостей (Node ≥ 18): эпики, план, шлюз, песочница, слепые линзы, вердикт, merge, хуки, самотест
  zones.json           карта зон — единственное место, где живут язык и команды проекта
  policy.json          дорожки, лимиты, классы опасности, strip-список песочницы
  rulings.md           решения человека (закон для всех последующих стадий)
  decisions.md         ADR-lite
  lessons.md           ≤60 строк; единственная память, которую импортирует CLAUDE.md
  metrics.jsonl        по событию на стадию
  epics/<epic>/        артефакты прогона (gitignored; в песочницу не попадают никогда)
.claude/
  agents/sep-*.md      12 ролей: триаж, проверка намерения, картограф, планировщик, аудитор плана, пробер, исполнитель,
                       инспектор, три слепые линзы, ученик
  workflows/sep-run.js оркестрация: тонкий цикл вокруг `sep next`
  skills/sep, sep-blind  драйвер и слепое ревью вне воронки
  settings.json        хуки принуждения
.githooks/pre-push     unit-ветки не пушатся; integration/main — только после lint+selftest
.github/workflows/separator-gate.yml   CI-пол без ИИ
examples/demo/         крошечный CLI, на котором воронка прогоняется в дымовом тесте
```

## Честные ограничения

- Пользовательские агенты `.claude/agents` регистрируются при старте сессии: после установки нужен перезапуск. До
  перезапуска воркфлоу работает в **мягком режиме** (роль читает свою карточку как промпт, ограничения инструментов
  не применяются) и говорит об этом в логе. Хуки `settings.json` подхватываются сразу.
- Хуки frontmatter агентов в текущей версии Claude Code не срабатывают — всё принуждение вынесено в глобальные хуки.
- `guard-bash`/`guard-blind` — фильтры по шаблонам команд: защита от дрейфа и ошибок, не от намеренного обхода.
  Физическая слепота обеспечивается песочницей вне проекта и `--restricted` (файловые инструменты ограничены каталогом).
- Слепые линзы требуют CLI `claude` (для другого вендора см. плейбук). Каждая линза — отдельный процесс, 40–60 с.
- Механические шаги (шлюз, вердикт, merge) выполняются агентом-раннером, потому что воркфлоу-скрипт не имеет доступа
  к файловой системе; раннер использует самую дешёвую модель.
- Мутанты — три «консервированные» мутации на изменённых строках, если в зоне нет `commands.mutate`.
